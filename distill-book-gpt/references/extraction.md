# 提取与核验

## EPUB

用 ZIP/OPF 读取元数据和 spine，用 Pandoc 读取有序原书块并抽出图片。脚本把 Div 容器展开以支持同一 XHTML 内多个章节与跨文件章节，保留块内表格、脚注、列表。`navigation.json` 保留 EPUB nav/NCX 的标题和目标，`toc-candidates.json` 同时列出实际标题；候选层级不一定等于章节层级。

检查 ZIP 的绝对路径、路径穿越、加密及异常膨胀；脚本的资源限制是保护处理环境的默认值，不是书籍格式上限。超限时核实后有针对性调整，不自动解除全部检查。拒绝引用外部图片而悄悄联网拉取。嵌入书内的图片是原文，不是外部知识。

对照 navigation、原文标题、spine 项首尾确认完整顺序。检查图书是否使用段落样式而非 heading 标记；脚本识别不了的标题由代理从 units 内容建立 split-plan，不把每个 XHTML 当一章。若全文仅在单一巨大块，先保真拆细该块，再确定边界。

Pandoc 不是“原文无损”保证：核对脚注、复杂表格、数学公式、特殊标点和图注。保留原始 OPF、XHTML/媒体在源文件中，转换有歧义时回看原文件。章节 Markdown 中的图像引用必须在 `02-chapters/assets/`；导出整书原文时脚本会为嵌入的 Markdown/HTML 图片重定位链接。

## PDF

按页提取文本块、字号、坐标、位图；有矢量绘图的页面同时保存整页渲染供检查，必要时裁出图表，加入 units 对应位置。页面截图不会被自动当成正文插图，以免用冗余页面替代真实插图提取。

优先书签，再印刷目录，最后正文标题与版面。多个信号冲突时以正文实际起止为准。印刷页码与 PDF 物理页常有偏移；至少检查开头、中间、结尾和每个章边界，不能只从目录推断统一偏移。章节中途起于一页时使用块索引，避免丢掉该页前一章内容或重复整页。

脚本默认按坐标排序，不保证多栏、浮动文本框或特殊排版正确。出现多栏时按实际阅读顺序重排块，记录处理方式。换行连字、页眉页脚、孤立页码需要依据页图核验后处理；不以字符串重复为唯一理由删除原文。非空 PDF 页的文本过少则标记 OCR 待核验，不能把扫描页当成空章跳过。

扫描页先使用实际可用的 OCR，再与页图抽样及关键内容逐页核对；混合 PDF 只修复需要识别的页。公式、密集表格、图表以局部截图保存，不凭 OCR 输出重建数字。没有 OCR 能力时报告哪些物理页阻塞。

## 完整性闸门

1. 校验原书归档 SHA256 与上传文件相同。
2. 对照 TOC 和所有源块，确认无漏章、重章、正文缺块；辅助材料保留。
3. 检查每章首尾、每个小节、所有图表/注释，尤其跨文件/跨页边界。
4. 确认所有相对图片链接可解析，不把缺图视为完成。
5. 确认章节 Markdown 是原文提取，不是生成的改写。
6. 确认 metadata 的未知值和冲突可见，摘要不借机补上原书没有的事实。

把检查结论简记到 `99-raw/extraction-report.json`。语义完整性由代理实际阅读负责，不用文件数量或字数阈值代替。
