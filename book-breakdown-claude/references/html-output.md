## 硬性约束

这几条不能妥协,违反任何一条都意味着产物不合格:

1. **单文件**。一个 `.html`,没有配套的 css/js/图片文件。
2. **零外部请求**。不引 CDN、不引 Google Fonts、不引外部图片。断网打开必须与联网打开完全一致。万一确实要放图,只能 base64 内嵌(见下)。
3. **纯原生**。不用 React/Vue/Tailwind 之类需要构建或 CDN 的东西。原生 HTML + CSS + 少量原生 JS 就够了。
4. **不用 localStorage / sessionStorage**。用户可能在各种环境里打开这个文件,存储行为不可预期,也没必要。

## 卡片列表思维导图

`assets/mind-template.html` 是形态参照,不是逐像素的规范。**照它的形,不照它的数。**

### 不能动的三条

这三条是这个形态存在的理由,违反任何一条就失去意义:

1. **卡片式,纵向顺读**。整页只能上下滚,不能出现需要横向拖动或缩放才能读全的区域。
2. **层级靠视觉自明**。不看文字,光看缩进、色块、字号,就能分清哪一层是哪一层。
3. **零外部依赖**。断网打开必须完全一致。

放射状脑图被排除掉就是因为违反前两条:节点一多必须缩放拖拽,眼睛要在画布上找路径。

### 可以按内容调的

下面这些是参数不是规矩,**按书的实际结构定,不要为了凑数注水,也不要为了塞进模板而合并本不该合并的内容**:

| 参数 | 参考范围 | 怎么定 |
|---|---|---|
| 卡片数 | 4~8 | 跟着书的主要部分/核心论点走。<4 说明切得太粗,>8 说明太碎该往上归并 |
| 每卡条目数 | 3~7 | 尽量让各卡接近,差太多会让网格高低参差 |
| 层级 | 2 或 3 | 见下 |
| 论证链步骤 | 4~8 | 跟着全书论证的实际环节走 |

模板的 CSS 已经泛化过,上面任何数字变动都不需要改样式(见「相对样例的改动」)。

### 第二层还是第三层

两层是默认:卡片标题 → `<li><strong>标签:</strong>陈述句`。

**第三层(`.leaf`)只在这一条确实挂着具体支撑物时才加**——案例、人名、公司名、数字、并列清单。抽象的话不要往下拆,拆了也还是抽象的。

```html
<li><strong>生活圈:</strong>消费者可能比华尔街更早发现畅销产品。
  <ul class="leaf">
    <li>妻子买的 L'eggs 丝袜 → 发现 Hanes</li>
    <li>购物中心是最好的调研场所</li>
  </ul>
</li>
```

判断标准很简单:**第三层是"这一条有硬证据"的标记**。如果每一条都挂了第三层,这个标记就不携带信息了,等于白加。一张卡片里通常只有一两条值得往下拆。

### 四个区块

整张导图对应第三步提示词的四问,不是另起炉灶:

| 区块 | class | 对应四问 | 内容来源 |
|---|---|---|---|
| 页头 | `.eyebrow` / `h1` / `.dek` | — | 书名 + 一句话路径概括 |
| 全书主旨 | `.core` | 这本书的主旨是什么 | `book-summary.md` 里讲主旨的部分 |
| 卡片网格 | `.grid` > `article` | 提纲纲领 + 重点论据 | `book-summary.md` 里讲提纲纲领和重点论据的部分 |
| 论证链 + 一句话记忆 | `.logic` / `.flow` / `.takeaway` | 论证过程是怎样的 | `book-summary.md` 里讲论证过程的部分 |

**所有文案从 `book-summary.md` 改写,不要回头重读原文另写一套。** 导图是全书总结的结构化再表达,两者观点矛盾就说明做错了。

### 各区块的写法

**`.dek`** 写的是"路径"不是"主旨"——主旨在 `.core` 里,这里写读者跟着这本书会走过什么过程,20~40 字。

**`.core`** 一到两句把核心命题说完整,用 `<b>` 高亮最关键的那个词组。`<b>` 全局只用一到两次,多了高亮就失效。下面的 `.stem` 连接竖线不要删,它和卡片上方的 `article::before` 短线配合,构成"主旨分叉出各部分"的视觉暗示。

**卡片标题**不写序号(序号在 `.num` 里),控制在 10 字以内,长了会把 `.chev` 挤到换行。

**每个 `<li>`** 统一 `<strong>标签:</strong>陈述句`。标签 2~4 字,是抓手;冒号后必须是能独立看懂的完整句子。

> 反面例子:`<strong>三个原则:</strong>作者提出了三个原则。`
> 这是目录不是导图,读者看完不知道是哪三个。要么拆成三条,要么写成 `<strong>原则:</strong>只买你能用两分钟讲清楚生意模式的公司。`

**`.step`** 的 `<strong>` 控制在 12 字以内,写动作不写概念(「用盈利与财务数据验证」而不是「财务分析」)。步骤之间插 `<div class="arrow">→</div>`,箭头数 = 步骤数 − 1。

**`.takeaway`** 是整本书压缩到一行,用逗号串联,不分点。

### 相对样例的改动

模板在保持视觉效果不变的前提下做了三处泛化,都是为了让上面那些参数真的可调:

1. **accent 配色改为按 6 循环**(`:nth-child(6n+2)` 这种写法)。原样例写死 `nth-child(2)`~`nth-child(6)`,第 7 张卡片开始就没有颜色了。
2. **新增第三层 `.leaf` 样式**。更小字号、更低不透明度、左侧细竖线,视觉上明确退到二级之后。
3. **`.flow` 从固定 6 列网格改为 flex 换行 + 显式 `.arrow` 元素**。原样例用 `grid-template-columns:repeat(6,...)` 配合 `.step::after` 伪元素画箭头,再用 `nth-child` 在两个断点上逐个隐藏行末箭头——步骤数一变,这套 nth-child 规则全错,会出现指向空白的箭头。改成 flex 后步骤数任意,行末的箭头正好表示"接下行",语义也对。窄屏下箭头整体隐藏。

除这三处外,配色、间距、字号、圆角、阴影、深色模式、断点、打印样式全部保持原样。

### 样式约束

- `:root` 的 CSS 变量 + `@media (prefers-color-scheme:dark)` 整套重定义,不要写死色值
- `color-scheme: light dark`
- 三档响应式:>820px 三列、820~520px 两列、<520px 单列
- `@media print` 打印样式
- 字体栈里的 `Inter` 只是优先项,**不能加 `@font-face` 或外部字体链接**,本地没有就自动降级

`04-book-mind/book-mind.html` 是可独立打开的完整 HTML。第六步把它嵌进最终页面时,复用同一套 class 名和 CSS 变量,不要另画一套。

## 最终页面结构

```
┌─────────────────────────────────────┐
│ 书名 / 作者 / 出版信息               │  封面区
├─────────────────────────────────────┤
│ [全书总结] [思维导图] [逐章摘要]     │  顶部导航(sticky)
├─────────────────────────────────────┤
│                                     │
│  § 全书总结                          │  完整展开,不折叠
│    主旨 / 提纲纲领 / 论证过程 / 重点论据 │
│                                     │
│  § 思维导图                          │  卡片列表,完整展开
│                                     │
│  § 逐章摘要                          │  默认折叠
│    ▸ 第1章 我是如何成长为一个选股者的  │  只放正文章节
│    ▸ 第2章 ...                       │
│                                     │
├─────────────────────────────────────┤
│ 生成信息 / 章节切分方式 / 免责说明    │  页脚
└─────────────────────────────────────┘
```

**为什么逐章摘要默认折叠、前两块不折叠**:全书总结和思维导图是这份报告的主体,用户打开就是要看这两块,折叠起来等于多一次点击;逐章摘要是"想细看时再看"的深度内容,全部展开会让页面长到失去导航感。这个默认状态符合"总结在前、细节在后"的阅读路径。

**页脚必须说清楚**:这份报告由 AI 从原书生成、章节切分方式(`toc.json` 里的 `extraction_method`)、生成时间。读者有权知道手里的东西是怎么来的,以及哪些环节可能出错。

## 交互

只需要三样,都用原生 JS,总共几十行:

1. **顶部导航锚点跳转**,导航栏 sticky 吸顶
2. **章节摘要展开/收起**,用 `<details>` / `<summary>` 就够了,不用写 JS
3. **"全部展开 / 全部收起"** 按钮,放在逐章摘要区的标题旁

不要加:搜索框、主题切换、进度条、动画过渡、打印样式。这些都是锦上添花,但每一样都增加出错面积,而这个文件必须一次生成就能用。

移动端能正常读:视口 meta 标签、正文最大宽度 `min(72ch, 100%)`、表格和代码块用 `overflow-x: auto` 包住。

## 样式

**直接继承 `assets/mind-template.html` 的设计系统**:同一套 `:root` CSS 变量、同一套深色模式重定义、同一套响应式断点、同一个字体栈。最终页面里嵌入的思维导图必须和 `book-mind.html` 长得一模一样,分两套样式会当场露馅。

`book_type` 只影响 accent 色的取向和文案语气,不改变版式。不要搞得花哨——这是一份用来读的文档,不是落地页。

- 字体栈沿用模板的 `Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。`Inter` 只是优先项,**不能加 `@font-face` 或任何外部字体链接**,本地没有就自动降级。
- 导图区的字号沿用模板;总结和章节摘要是长文阅读,正文放大到 16~18px、行高 1.7~1.8。中文长文本行高要比英文大。
- 颜色全部走模板 `:root` 上的 CSS 变量,不要写死色值。
- 用 `@media (prefers-color-scheme: dark)` 支持深色模式,给 `body` 明确的背景色——不给背景色的话,深色模式下会出现黑底黑字。
- 一级标题、卡片标题、章节标题三套层级要拉开对比度,靠字号和字重,不要靠颜色。

## 图片

**默认一张图都没有。** 这个文件装的是全书总结、思维导图和章节摘要——全是文字产物,不是原书的排版复刻。`02-chapters/assets/` 里那些图是给章节原文用的中间产物,**不要主动捞出来往成品里塞**。

只有一种情况放图:某份总结的内容本身离不开那张图(一张关键图表、一个必须看图才能理解的示意)。这时候只放这一张,转成 base64 data URI:

```html
<img src="data:image/png;base64,iVBORw0KGgo..." alt="图3-1 Hanes 公司股价走势">
```

必须内嵌而不能写 `src="assets/xxx.png"`,否则文件一拖出目录就裂图,违反"零外部请求"。`alt` 沿用原书图注,不要留空。

base64 会让体积比原文件大约 33%,这是编码开销,正常。真放了图就在收尾报告里说明放了几张。
