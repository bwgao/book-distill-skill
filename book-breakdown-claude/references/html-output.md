## 硬性约束

这几条不能妥协,违反任何一条都意味着产物不合格:

1. **单文件**。一个 `.html`,没有配套的 css/js/图片文件。
2. **零外部请求**。不引 CDN、不引 Google Fonts、不引外部图片。断网打开必须与联网打开完全一致。万一确实要放图,只能 base64 内嵌(见下)。
3. **纯原生**。不用 React/Vue/Tailwind 之类需要构建或 CDN 的东西。原生 HTML + CSS + 少量原生 JS 就够了。
4. **不用 localStorage / sessionStorage**。用户可能在各种环境里打开这个文件,存储行为不可预期,也没必要。

## 最终页面结构

```
┌─────────────────────────────────────┐
│ 书名 / 作者 / 出版信息               │  封面区
├─────────────────────────────────────┤
│ [全书总结] [思维导图] [逐章摘要]     │  顶部导航(sticky)
├─────────────────────────────────────┤
│                                     │
│  § 全书总结                          │  完整展开,不折叠
│                                     │
│  § 思维导图                          │  卡片列表,完整展开
│                                     │
│  § 逐章摘要                          │  默认折叠
│    ▸ 第1章 我是如何成长为一个选股者的  │  只放正文章节
│    ▸ 第2章 ...                       │
│                                     │
├─────────────────────────────────────┤
│ 生成信息 / 章节切分方式 / 免责说明    │  页脚
└─────────────────────────────────────┘
```

**为什么逐章摘要默认折叠、前两块不折叠**:全书总结和思维导图是这份报告的主体,用户打开就是要看这两块,折叠起来等于多一次点击;逐章摘要是"想细看时再看"的深度内容,全部展开会让页面长到失去导航感。这个默认状态符合"总结在前、细节在后"的阅读路径。

**页脚必须说清楚**:这份报告由 AI 从原书生成、章节切分方式(`toc.json` 里的 `extraction_method`)、生成时间。读者有权知道手里的东西是怎么来的,以及哪些环节可能出错。

## 图片

**默认一张图都没有。** 这个文件装的是全书总结、思维导图和章节摘要——全是文字产物,不是原书的排版复刻。`02-chapters/assets/` 里那些图是给章节原文用的中间产物,**不要主动捞出来往成品里塞**。

只有一种情况放图:某份总结的内容本身离不开那张图(一张关键图表、一个必须看图才能理解的示意)。这时候只放这一张,转成 base64 data URI:

```html
<img src="data:image/png;base64,iVBORw0KGgo..." alt="图3-1 Hanes 公司股价走势">
```

必须内嵌而不能写 `src="assets/xxx.png"`,否则文件一拖出目录就裂图,违反"零外部请求"。`alt` 沿用原书图注,不要留空。

base64 会让体积比原文件大约 33%,这是编码开销,正常。真放了图就在收尾报告里说明放了几张。
