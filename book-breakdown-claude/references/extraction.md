## EPUB 路径

EPUB 是一个 zip 包,内部有完整的结构化目录,所以章节切分是确定的,不需要猜。

### 1. 解包

用 `unzip` 或任何等价的解包能力把 EPUB 解到临时目录。不需要第三方库——zip 解包能力在所有环境里都有(shell 的 `unzip`、Python 标准库的 `zipfile`、或环境内置的归档工具)。

### 2. 找到 OPF 文件

`META-INF/container.xml` 里的 `<rootfile full-path="...">` 指向 OPF 文件(通常是 `OEBPS/content.opf` 或 `content.opf`)。不要假设路径,一定从 container.xml 读。

### 3. 从 OPF 拿两样东西

- `<metadata>`:第二步的元数据来源(title、creator、publisher、date、identifier/ISBN、language)
- `<spine>`:**阅读顺序**,一串 `idref`,按 `<manifest>` 映射到实际的 XHTML 文件

### 4. 拿目录标题

EPUB 3 看 `nav.xhtml`(`<nav epub:type="toc">`),EPUB 2 看 `toc.ncx`(`<navMap>` 里的 `navPoint`)。两者都可能存在,优先 nav.xhtml。

这里给出的是**标题和层级**;真正的**顺序**以 spine 为准。目录里可能漏掉某些内容文件(常见于版权页、广告页),spine 则是完整的。

### 5. 对齐 spine 与目录,切分章节

按 spine 顺序遍历 XHTML 文件,用目录里的锚点把它们归类到各个章节。三种常见情况:

- **一文件一章**(最常见):直接一一对应
- **一文件多章**:目录项带 `#anchor`,按锚点在文件内切分
- **一章多文件**:目录项之间跨了多个 spine 文件,合并成一章

### 6. 判定前置/正文/后置

按目录标题的关键词分类:

- 前置(`a`):序、自序、推荐序、译者序、前言、导读、引言、致读者、Introduction、Preface、Foreword
- 后置(`z`):后记、结语、附录、致谢、译后记、参考文献、索引、注释、Afterword、Appendix、Acknowledgments

前置编号 `a01`、`a02`……后置编号 `z01`、`z02`……都按在书里出现的先后排。
- 其余归正文(`ch`),按出现顺序编号

判不准的时候看位置:出现在第一个正文章节之前的归前置,出现在最后一个正文章节之后的归后置。

**跳过不要的内容**:封面页、版权页、出版说明、广告页、空白页。这些在 spine 里存在但没有阅读价值,不要生成章节文件,但要在 `toc.json` 里记一条 `"skipped": true` 说明跳过了什么,便于事后核对。

## PDF 路径

PDF 没有结构化目录,可靠性天然低一档。两条路,优先级明确。

### 路径 A:书签大纲(优先)

绝大多数正规出版的 PDF 带书签大纲(outline / bookmarks),里面有标题和目标页。有大纲就用大纲,它是出版方自己标的,可信度接近 EPUB 的目录。

读大纲需要 PDF 库(`pypdf`、`pdfplumber`、`PyMuPDF` 等)。先检测环境里有没有,有就用。都没有且装不上,直接告诉用户环境不支持 PDF 解析,不要硬来。

拿到大纲后:按大纲的页码切分,每个章节抽取对应页范围的文本。正常往下推进,不需要用户确认。

### 路径 B:标题识别(降级,**必须确认**)

没有大纲时才走这条。做法:

1. 抽取全文文本,保留页码和每行的字号/字重信息(`pdfplumber` 和 `PyMuPDF` 都能给到字符级属性)
2. 找出正文的基准字号(出现频率最高的字号)
3. 显著大于基准字号、或加粗且独占一行的短行,是候选标题
4. 用书前的目录页(通常在前 10 页)交叉验证候选标题——目录页列出的标题文本应该能在正文里匹配上
5. 排除页眉页脚:在多页重复出现的相同短文本

**然后停下来。** 把识别结果整理成一张表给用户:

```
序号  类型  标题                    起始页  结束页
1     前置  推荐序                  1       6
2     前置  前言                    7       12
3     正文  第1章 我是如何成长为...   13      28
...
```

明确问用户:章节有没有漏、有没有多切、起止页对不对。得到确认后再生成章节文件。

为什么必须停:标题识别的错误不会立刻暴露,要到第六步看最终 HTML 才发现,那时候三、四、五步全做完了,返工成本极高。花一分钟确认,省掉一次全流程重做。

### 扫描版 PDF

如果抽出来的文本是空的或全是乱码,说明是扫描件,需要 OCR。OCR 超出本技能范围:告诉用户这是扫描版,需要先 OCR 转成文字版 PDF 再来,不要尝试硬识别。

## toc.json 格式

```json
{
  "source_format": "EPUB",
  "extraction_method": "epub-nav",
  "total_entries": 24,
  "entries": [
    {
      "file": "a01-preface.md",
      "type": "frontmatter",
      "order": 1,
      "title": "推荐序",
      "source_ref": "OEBPS/text/part0002.xhtml",
      "skipped": false
    },
    {
      "file": "ch01.md",
      "type": "chapter",
      "order": 3,
      "title": "第1章 我是如何成长为一个选股者的",
      "source_ref": "OEBPS/text/part0005.xhtml",
      "skipped": false
    },
    {
      "file": null,
      "type": "copyright",
      "order": 0,
      "title": "版权页",
      "source_ref": "OEBPS/text/part0001.xhtml",
      "skipped": true
    }
  ]
}
```

`extraction_method` 取值:`epub-nav`、`epub-ncx`、`pdf-outline`、`pdf-heading-detection`。这个字段要带到最终 HTML 的页脚,让读者知道章节切分的可靠性来自哪里。

PDF 的条目额外带 `page_start` / `page_end`。

## Markdown 转换规则

目标是**留下语义,丢掉排版**。章节原文是给后面的总结步骤读的,不是给人直接阅读的,所以排版细节没有价值,语义结构有价值。

保留:

| 原文元素 | Markdown |
|---|---|
| 章节标题 | `#`(每个文件只有一个一级标题) |
| 小节标题 | `##`、`###`,按原书层级 |
| 正文段落 | 普通段落,段间空行 |
| 强调 | `**粗体**`、`*斜体*` |
| 引用 | `>` |
| 列表 | `-` / `1.` |
| 表格 | Markdown 表格;结构太复杂转不了就保留 HTML `<table>` |
| 图片 | `![说明](assets/xxx.png)` |
| 脚注 | `[^1]` + 文末定义 |
| 代码/公式 | 代码块;数学公式尽量保留 LaTeX 或原文字符 |

丢掉:页眉、页脚、页码、装饰性分隔线、字体字号颜色、`<div>` `<span>` 之类的纯排版标签。

**不要改写原文一个字。** 这一步是格式转换,不是编辑。错别字、奇怪的断句、译文的别扭之处全部原样保留——判断哪里是错的不是这一步的职责,而且改了会污染后面的总结。

## 图片处理

- 全部存到 `02-chapters/assets/`
- 命名:`<章节文件名去扩展名>-fig<两位序号>.<原扩展名>`,例 `ch03-fig01.png`
- 保留原格式和原分辨率,中间产物保持无损
- Markdown 里的 alt 文本用原书的图注;没有图注就写 `图N-M`
- 纯装饰性图片(章节起始的花纹、页边装饰)不要提取

## 常见坑

**spine 顺序 ≠ 目录顺序**:目录是出版方给读者看的,可能重排或省略;spine 是真实的阅读流。以 spine 为准。

**注释章节**:有些书把所有章节的注释集中放在书末的"注释"里。这种情况下它是 `z` 类型的独立文件,不要试图拆散塞回各章。

**多卷书**:书里分"第一部分/第二部分"这种大层级时,`toc.json` 的条目加一个 `part` 字段记录所属部分,但章节编号仍然全书连续(`ch01` 到 `chNN`),不要每部分重新从 01 开始——重新编号会导致文件名冲突。

**繁体/异体字**:原样保留,不要转换。`output_language` 由元数据决定,与原文字形无关。

**超长章节**:单章超过约 5 万字时,在第五步做摘要可能超出上下文。这种情况下把该章按小节切成几段分别喂入,再合并成一份摘要,并在摘要末尾注明做过分段处理。
